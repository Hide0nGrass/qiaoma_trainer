# 部署成公网站点

这个项目是「一个 Node 进程 + 一堆静态文件」，没有数据库，状态全在浏览器 localStorage 里。所以部署只有两件事：**把进程跑起来**、**给它一个能访问的模型端点**。

---

## 先看三个前提

1. **密钥只能放在服务端**。`/api/coach` 和 `/api/read` 由 `server.mjs` 代理上游，浏览器里永远看不到 key。`coach.config.json` 已经在 `.gitignore` 里，线上请用环境变量。
2. **本机网关 `127.0.0.1:3456` 在线上不存在**。那是你电脑上的 claude-code-router，部署到云上必须换成公网可访问的 Anthropic 兼容端点。
3. **没有 key 也能上线**。所有判定、读牌概率、四档评级都是本地引擎算的，AI 只是讲解；`/api/health` 会返回 `coach:false`，页面按 A / 作答后自动给本地文案，不会报错。

## 环境变量

| 变量 | 作用 | 例子 |
| --- | --- | --- |
| `PORT` | 监听端口（平台通常自动注入） | `8788` |
| `HOST` | 绑定地址，线上用 `0.0.0.0` | `0.0.0.0` |
| `COACH_API_KEY` | 上游 key | `sk-ant-...` |
| `COACH_BASE_URL` | Anthropic 兼容根地址（不带 `/v1`） | `https://api.anthropic.com` |
| `COACH_MODEL` | 模型名 | `claude-3-5-haiku-latest` |

服务端调的是 `${COACH_BASE_URL}/v1/messages`（Anthropic Messages 协议，带 `anthropic-version` 头）。**如果只有 OpenAI 兼容的 key**（DeepSeek 官方、百炼、硅基流动等），要么换一个提供 Anthropic 兼容入口的供应商，要么在同一个容器里跑一层 `claude-code-router` 之类的转换网关，再把 `COACH_BASE_URL` 指向 `http://127.0.0.1:3456`。

---

## 方案 A：托管平台（最快，推荐先跑通）

以 Railway / Render / Zeabur 这类平台为例，它们都支持「连 GitHub 仓库 → 自动装依赖 → 给一个 https 域名」：

1. 仓库根目录已有 `package.json`（`start: node server.mjs`）和 `Dockerfile`，平台会自动识别；没有 Dockerfile 时用 `npm start` 也一样。
2. 平台设置里加环境变量：`HOST=0.0.0.0`、`COACH_API_KEY=...`、`COACH_BASE_URL=...`、`COACH_MODEL=...`。
3. 部署完打开 `https://<你的域名>/api/health`，看到 `{"ok":true,"coach":true}` 就通了。
4. 绑定自定义域名，平台自动签 HTTPS。

注意：这类平台的免费实例会休眠，冷启动第一次打开会慢几秒；`/api/coach` 是 SSE 流式返回，平台需要允许长连接（默认都支持）。

## 方案 B：自己的云服务器（VPS）

一台 1 核 1G 的轻量服务器就够（进程内存约 60MB）：

```bash
# 1. 装 Node 20+
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs git nginx

# 2. 拉代码
cd /opt && sudo git clone https://github.com/<你>/qiaoma_trainer.git qiaoma
cd qiaoma

# 3. 用 systemd 常驻
sudo tee /etc/systemd/system/qiaoma.service >/dev/null <<'EOF'
[Unit]
Description=qiaoma trainer
After=network.target

[Service]
WorkingDirectory=/opt/qiaoma
Environment=HOST=127.0.0.1
Environment=PORT=8788
Environment=COACH_BASE_URL=https://api.anthropic.com
Environment=COACH_MODEL=claude-3-5-haiku-latest
EnvironmentFile=-/opt/qiaoma/.env
ExecStart=/usr/bin/node server.mjs
Restart=always

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl enable --now qiaoma
```

`.env` 里只放一行 `COACH_API_KEY=...`，`chmod 600`。

Nginx 反代 + 证书：

```nginx
server {
  server_name mahjong.example.com;
  location / {
    proxy_pass http://127.0.0.1:8788;
    proxy_http_version 1.1;
    proxy_set_header Connection '';
    proxy_buffering off;        # SSE 不缓冲
    proxy_read_timeout 300s;
  }
}
```

```bash
sudo certbot --nginx -d mahjong.example.com
```

`proxy_buffering off` 是必须的，否则点评会「一次性蹦出来」而不是逐字。

## 方案 C：纯静态（不要 AI）

如果只想让别人练拆搭、不需要讲解，可以把 `public/` + `engine.mjs`、`opponent.mjs`、`read.mjs` 拷到任何静态托管（Cloudflare Pages、Vercel、对象存储 + CDN）——前端是原生 ESM，浏览器直接 import，不需要打包。

代价：`/api/health` 不存在，`S.coachOff` 会一直是 true，按 A 时提示「未接入 AI」。其余功能（判定、四档评级、牌墙、结构分组、收藏、错题本、摇铃题库、危险牌榜）全部照常，因为算力都在浏览器里。

## 上线前自查

- [ ] `git grep -n "ccr-profile\|sk-ant\|github_pat"` 没有命中（仓库里不含密钥）
- [ ] `/api/health` 返回 `coach:true`，且 `gateway` 是你配的地址
- [ ] 手机打开一次：摇铃的牌不能横向溢出（试 360px 宽）
- [ ] `curl -N https://<域名>/api/read -X POST -H 'content-type: application/json' -d '{"mode":"answer",...}'` 能看到逐块 `data:` 输出（说明 SSE 没被 CDN 缓冲）
- [ ] 控制台无报错；断网状态下页面仍能出题（本地引擎兜底）

## 国内访问的两个坑

1. **备案**：域名解析到中国大陆的服务器必须有 ICP 备案，否则 80/443 会被阻断。想免备案就用海外/香港节点，或直接用平台给的 `*.vercel.app` / `*.railway.app` 域名。
2. **上游可达性**：如果模型端点在境外，服务器到上游的链路可能不稳，建议把 `COACH_BASE_URL` 指到国内可访问的中转（同样要 Anthropic 协议），并保留 12s 超时后的本地兜底——现在的实现里超时会退回本地结论，不会卡住页面。
